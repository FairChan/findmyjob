UI p95 的口径是浏览器中确认/提交到可核验终态，包含 Server Action、必要导航/刷新和渲染；它是本地诊断项。旧 mutation HTTP 脚本的1000ms预算不能直接当作此 UI 的通过线；HTTP 200 或隐藏的404也不是成功。现有 browse 的 HTTP预算及 upload 的测量口径未在本修复中修改或重验。

此前四轮full失败记录保留：重复会话预检耗尽共享滚动认证桶、协调回执连接/EOF失败，以及首次预检连接超时，均不计为通过。最终驱动仅在每VU成功预检一次；每个fresh学生仍经真实页面及Action独立鉴权。仅HTTP0的只读预检和幂等记账可有限重试，明确拒绝及业务操作不重试；未修改限流/安全守卫或减少并发负载。底层传输偶发失败原因未被证明，以上数据只能支持这次本地正确性验收。

通过条件优先是全部预期客户端/已开始迭代都有终态，未来 epoch 屏障与确认窗口有效、实际 UI 结果符合预期，以及全 run scope 的只读 SQL 能对齐每条申请、事件、JobView、unlock、wallet 和双向账本引用。full 的固定排程消耗完毕必须失败，不能循环账户掩盖耗尽。只有获准在真实目标环境完成网络、数据库/应用资源及运维演练，才能补充外部容量结论。
