# PRD · FindMYJob

> v0.2 · 2026-11-03 · 本文件是自动开发的需求依据，与其他文档冲突时以本文件为准。
> 任务拆分见 `TASKS.md`；数据模型见 `../prisma/schema.prisma`；技术约定见 `ARCHITECTURE.md`；待定事项见 `DECISIONS.md`；子处理者见 `SUBPROCESSORS.md`。
> v0.2 依据 2026-11-02 团队会议和 2026-11-03 的安全审计修订；会上没拍板的数字全部做成 §5 的系统参数。

**定位**：FindMYJob 帮在马来西亚的中国留学生（之后扩展到其他国际生）找实习和工作；注册不限国籍。界面一看就懂，注册简单，资料分步完善。学生免费，但查看职位详情有额度，邀请同学可以解锁更多；企业在人才库里搜人，用点数解锁联系方式。先公益试点（`billing.enabled=false`），之后转收费。

## 0. 名词

| 名词 | 含义 |
|---|---|
| 人才库 | 满足以下全部条件的学生档案：visibility=PUBLIC、学校已认证、完成度 ≥ `talentPool.minCompleteness`、账号 ACTIVE |
| 解锁 | 企业花点数查看某个学生的全名、联系方式和原始简历。同一企业对同一学生只需解锁一次，企业内全员共享 |
| 点数（credit） | 企业钱包里的虚拟额度。公益期免费发放，收费期购买 |
| 投递 | 学生主动申请某个职位。投递后企业自动获得该学生的联系方式，不扣点 |
| 邀请 | 企业邀请学生投递某个职位。不扣点，占用邀请配额；学生接受即视为投递 |
| 公益期（Pilot） | `billing.enabled=false` 的阶段，所有付费功能以 0 元或赠送点数运行 |
| 查看额度 | 学生能打开的职位详情数（§2.5） |
| 有效邀请 | 学生邀请的新用户满足 §2.5 条件后才算数，用来增加查看额度 |
| 标准化简历 | 在线结构化简历；HR 看到的是统一格式，PDF 只是可选附件 |
| 关联搜索 | 关键词扩展到同义词组后再匹配的搜索模式（§2.4） |
| 代管企业 | 由平台运营代建账号、代发职位的企业，之后可以移交给企业自己（§4） |

## 2. 学生端

### 2.1 注册与认证
- 邮箱 + 密码 + 邮箱验证码 + Cloudflare Turnstile 人机验证。支持 `?ref=邀请码`。
- 人机验证覆盖 4 个入口：注册、登录、发验证码、找回密码。直接调用接口（绕过页面）也必须校验。
- **注册上限**（只限学生）：已验证、ACTIVE 的学生数达到 `signup.studentCap` 后，注册页显示「名额已满」，带邀请码进来的也一样；企业注册不受上限影响；达到 `signup.warnRatio` 时给运营发一次通知。未验证邮箱的账号不占名额，超过 `signup.unverifiedTtlHours` 小时仍未验证就删除。上限是软上限，并发时可能略超（已接受风险）。
- 所有提示都不能透露某个邮箱是否已注册：用已注册的邮箱注册时，返回和新邮箱一样的结果，并给该邮箱发一封「有人尝试用你的邮箱注册」提醒；找回密码时邮箱不存在也提示已发送；登录失败统一提示「邮箱或密码错误」。
- 注册时的勾选项：
  - 用户协议、隐私政策（必选）
  - 「加入人才库：允许认证企业查看我的匿名档案，并在付费解锁后查看我的联系方式」（可选，默认不勾，决定 visibility）
  - 每次同意或撤回都写入 Consent（含版本号、IP、UA）。
- 学校认证：选择学校 → 输入学校邮箱（`@` 后面的整段必须精确等于 `School.emailDomains` 里的某一项）→ 收验证码 → 通过后写入 `schoolVerifiedAt`。学校邮箱统一转小写，同一个学校邮箱只能认证一个账号。验证码每个用户每小时最多发 `limits.otpSendsPerHour` 次，每个目标邮箱每天最多 `limits.otpSendsPerEmailPerDay` 次；验证码只存哈希。没有学校邮箱的可上传学生证，由运营人工审核（M6）。
- 学校未认证的学生**不进入人才库**，但可以投递。

### 2.2 档案（Onboarding 向导，4 步，必经流程）
- 注册后必须走完向导；顶部显示「第 n / 4 步」，每一步可以保存后退出，下次回到未完成的那一步。
1. **基本信息**：姓名、学校、学历层次、专业、毕业年月、CGPA（可选，0.00–4.00）、国籍、**工作资格**（马来西亚公民 / PR / 学生准证 / 家属准证 / 毕业后需工作准证 / 其他）
2. **求职意向**：实习 / 全职 / 兼职（多选）、最早到岗日期、意向州属（多选）、意向行业、期望薪资（MYR / 月，可不填）
3. **能力**：语言（中文 / 英文 / 马来文 / 其他 + 程度）、技能标签（自由输入 + 推荐）、一句话介绍、自我介绍
4. **经历**：教育、实习/工作、项目、校园活动、奖项（每类可多条）；上传简历 PDF（可选；≤ 5MB、≤ `resume.maxPages` 页、不收加密 PDF；可多份，指定一份为主简历）

- 联系方式（手机、联系邮箱、WhatsApp、微信、LinkedIn）单独一页，页面提示「只有在你投递，或企业付费解锁后才可见」。
- **档案完成度（0–100）**：基本信息 30、求职意向 15、能力 20、经历 20、简历 PDF 10、联系方式 5。不传 PDF 最高刚好 90。完成度低于 `talentPool.minCompleteness` 不进入人才库；低于 `apply.minCompleteness` 不能投递，点投递时带到向导里第一个没填完的步骤。

### 2.3 隐私中心
- 人才库可见性开关（PUBLIC / HIDDEN）。关闭 = 撤回 TALENT_POOL 同意。
- 屏蔽企业：搜索企业名称加入屏蔽列表。被屏蔽的企业搜不到该学生；即使之前已解锁，也不再显示联系方式。
- 「谁看过我」：最近 90 天查看过我档案的企业（企业名 + 时间）。
- 「谁解锁了我」：解锁记录（企业名 + 时间）。
- 数据权利：
  - 导出我的数据（JSON + 简历文件打包）。邮件里只放站内链接；本人登录后，在 24 小时内点开，服务端现场生成一个有效期不超过 5 分钟的下载签名。
  - 申请删除账号：软删除，立即从人才库移除；30 天后物理删除联系方式和简历文件（包括对象存储里的全部历史版本），档案匿名化

### 2.4 求职
- 访客只能看职位列表；看详情要登录，并受 §2.5 的查看额度限制。
- **搜索两种模式**：
  - 精确（默认，`search.defaultMode`）：每个关键词都要在标题、技能、职位类别、公司名、行业名里出现。
  - 关联：每个关键词扩展成「原词 + 同组同义词」（运营维护的同义词表，双向），命中任意一个就算。
  - 精确结果少于 `search.relatedFallbackBelow` 条时，在下方加一栏「相关职位」。同一职位只出现一次，精确命中排在前面；不区分大小写，中英文都能命中（"Finance" 能搜到「财务」那一组）。
- **筛选**：保留类型、州属、职位类别、语言要求、「接受学生准证 / 可协助办理工作准证」；新增公司行业（两级，选大类即包含全部子类）、公司定位标签（任一命中）、公司规模、薪资档（`jobs.salaryBands`，职位薪资上限 ≥ 档位即命中；选了薪资档时隐藏薪资的职位不显示，也不能借筛选反推它的薪资）。P2：地点（预设地标 / 商圈 / 地铁站 + 半径，联动地图；不选就不限）。
- 排序：按发布时间或相关度。
- 职位详情 → 投递（选择简历，附言 ≤ 500 字）。同一职位只能投递一次，可以撤回。职位详情页可以「举报」（§2.6）。
- 我的投递：状态时间线（已投递 → 已查看 → 入围 → 面试 → Offer → 录用 / 未通过 / 已撤回）。
- 我的邀请：接受（自动生成投递）或婉拒。
- 通知：站内通知 + 邮件（见 §6）。

### 2.5 查看额度与邀请
- **额度**（`studentQuota.*`，开关 `studentQuota.enabled`，关闭后不限）：
  - 登录后可看 `studentQuota.baseJobViews` 个职位详情；每 `studentQuota.tierSize` 个有效邀请多 `studentQuota.tierBonus` 个；累计 `studentQuota.unlimitedAt` 个有效邀请后不限。
  - 额度来源：BASE（基础）、REFERRAL（邀请）、PURCHASE（预留，`billing.studentEnabled=false` 时不显示任何购买入口）、ADMIN_GRANT（运营加额度，必须写原因）。
- **什么算看了一个**：学生**主动点开**某个职位详情才计 1 次；同一职位以后再看不计；页面自动选中、预取、刷新都不计；已投递的、企业邀请投递的职位不计也不锁。额度用完后，新职位只显示标题、公司、州属，以及「邀请同学解锁」按钮。
- **有效邀请**：被邀请人通过邀请链接注册、邮箱已验证、完成度 ≥ `referral.minCompleteness`（`referral.requireSchoolVerified=true` 时还要学校已认证）。一个被邀请人只记给一个邀请人；自己邀请自己不算（邮箱规范化后比较：转小写，gmail 去掉点和 +tag）；作废的不计；被邀请人之后删号不收回已给的额度。每个邀请人每天最多 `referral.maxQualifiedPerDay` 个邀请生效，超出的保持「待生效」，次日自动重新判定。
- **额度页**：已用 / 总额、邀请链接和复制按钮、3 / 6 / 9 / 12 进度、已邀请列表（脱敏名、完成度、状态）。

### 2.6 反诈专区
- 公开页，内容分三类：诈骗案例（可带视频）、求职指南、紧急联系方式（马来西亚报警电话 999；使馆领事保护电话由运营核实后填写，不编号码）。内容由运营在后台维护。
- 职位详情页有「举报」，原因五种：要求先交钱、虚假薪资、疑似非法工作、信息与实际不符、其他（可填说明）。每个用户每天最多举报 `limits.jobReportsPerDay` 次。举报进运营队列。

## 3. 企业端

### 3.1 入驻与认证
- 企业用户注册（邮箱 + 密码 + Turnstile）→ 创建企业：法定名称、展示名（中 / 英）、SSM 注册号、行业（两级代码，例如 `finance.bank`）、规模、官网、地址 / 州属、简介、Logo。
- 公司定位标签（世界 500 强、跨国企业、马来西亚龙头、中资出海、国企、校友企业、马来西亚华资）只由运营设置，企业不能自己标。
- 上传认证材料（SSM 证明或营业执照，PDF/PNG/JPG，单个 ≤ 10MB，最多 5 个；经统一的上传接口，服务端校验）→ 状态 PENDING → 运营审核（SOP 见 §4）→ VERIFIED 或 REJECTED（附原因，可重新提交）。
- 认证通过：创建钱包；公益期立即发放点数（补足到 `pilot.monthlyCredits`），之后每月 1 日补足一次，**不累加**。
- 团队：OWNER / ADMIN 通过邮箱邀请成员。邀请链接 7 天有效、只能用一次，并绑定被邀请的邮箱：接受者必须用同一个已验证的邮箱登录。公益期团队最多 `team.maxMembers` 人；席位数之后受套餐限制（M8 起生效）。被移除的成员下一次操作就失效。
- 企业公开主页：Logo、简介、在招职位；创始合作伙伴显示徽章。

### 3.2 人才库搜索
- **筛选**：学校、专业关键词、学历层次、毕业年份（区间）、求职意向类型、语言及最低程度、工作资格（多选）、技能（任一 / 全部）、意向州属、最早到岗时间、最近活跃时间。
- **关键词**：匹配专业、技能、一句话介绍、经历标题。
- **排序**：最近活跃（默认）/ 完成度 / 毕业年份。每页 20 条，最多翻到第 `talentSearch.maxPage` 页。
- **匿名卡片字段**：学生 ID、**脱敏姓名**（中文名取姓 + "同学"，含复姓；非中文名取首字母 + "."）、学校、学历、专业、毕业年月、工作资格、语言、技能、一句话介绍、最近活跃、本企业是否已解锁。
- **详情页（未解锁）**：卡片字段 + 经历。**所有自由文本**（一句话介绍、自我介绍、每个技能标签、教育的专业和描述、经历的标题、机构和描述、结构化简历预览）中的邮箱、电话、URL、微信号一律替换为「[已隐藏]」。不提供原始 PDF。
- 学生不在人才库、或已屏蔽本企业时，直接按 id 打开详情页也返回「不存在」。
- 每打开一次详情页记录一条 ProfileView。
- **收藏夹**：企业内共享，可建多个文件夹，可加备注。
- **防爬**：每个企业成员每天查看详情 ≤ `limits.profileViewsPerDay`，每家企业合计 ≤ `limits.companyProfileViewsPerDay`（两者同时生效）；同一学生当天被同一企业重复查看只计 1 次；每个成员每天最多翻 `limits.searchPagesPerDay` 页搜索结果；解锁 ≤ `limits.unlocksPerDay`；人才库不提供批量导出。触发上限时写审计。

### 3.3 解锁
- 详情页按钮「解锁联系方式（消耗 N 点）」→ 二次确认 → 原子事务：校验（学生可见、未屏蔽本企业、账号正常）→ 创建 TalentUnlock → 扣点 → 记账 → 审计日志 → 提交后异步通知学生。
- 已解锁（或该学生投递过本企业的职位）：显示全名、联系方式；可下载简历 PDF，**每页带水印**：「仅供 {企业名} 招聘使用 · {日期} · {操作人 ID}」。
- 余额不足：收费期引导购买；公益期提示「下月 1 日补发」。
- 重复解锁不扣点。

### 3.4 职位与投递管理（轻量 ATS）
- 发布职位：标题、类型、职位类别、描述、要求、福利、工作模式、州属 / 城市、薪资区间（可隐藏）、语言要求、技能、是否接受学生准证、是否可协助办理工作准证、招聘人数、截止日期。
- 试点期所有职位都要运营审核：`jobs.autoPublishAfter` 默认 1000（DECISIONS A27），企业通过审核的职位数达到该值后才自动发布。
- 职位数受套餐限制（M8 起）。
- **投递看板**：按状态分列，拖拽改状态；每次变化写 ApplicationEvent 并通知学生；可写内部备注（学生不可见）。移动端用列表视图。
- **标准化列表**：看板之外的另一种视图，一行一个人：姓名、学校、专业、学历、毕业年月、CGPA、工作资格、语言、实习数、校园经历数、完成度；可按 CGPA、毕业年月、完成度排序。HR 一眼扫完。
- **邀请投递**：在人才卡片或详情页点「邀请投递」→ 选职位 → 写附言 → 占用邀请配额。超过 `invitations.expireDays` 天未处理自动过期。

### 3.5 账单（M8 之前只显示余额和流水）
- 余额、点数流水（发放 / 购买 / 解锁 / 退款 / 调整）
- 购买套餐和点数包（M8）：银行转账（上传回单 → 运营确认）/ 在线支付（FPX、银行卡）
- 订单列表、发票下载

## 4. 运营后台
- **数据看板**：学生注册数和完成度分布、认证企业数、职位数、投递数、解锁数、点数发放与消耗；按学校、按周的趋势；**注册人数 / 上限进度**
- **企业认证队列**：查看材料，通过 / 驳回（填原因）。认证 SOP：通过公开渠道（SSM 记录、官网、公开电话）回拨核实，不用材料里自带的联系方式
- **代建企业**：运营建企业并直接认证 → 以平台身份代发职位（不需要审核）→ 移交给企业邮箱（复用团队邀请机制，移交后平台账号失去该企业的权限）。每一步都写审计
- **职位审核队列**
- **举报队列**：处理或驳回，写审计
- **学生管理**：搜索、查看、停用 / 恢复（停用后该学生的所有会话立即失效）、人工学校认证；给学生加查看额度（ADMIN_GRANT，必须写原因）
- **企业管理**：停用（停用后成员下一次请求即被拒）、标记创始合作伙伴、设置公司定位标签、调整点数（必须填原因）
- **增长与风控**：邀请记录（可作废，作废后邀请人的额度立即重算）、同义词表、反诈内容管理
- **订单管理**：确认银行转账到账 → 自动发点 / 开通套餐
- **学校管理**：名称、邮箱后缀、是否合作
- **合作伙伴管理**：首页背书展示（名称、Logo、类型、排序）
- **系统设置**：功能开关和参数（见 §5）
- **审计日志查询**
- **数据请求处理**：导出 / 删除 / 更正
- 运营人员每人一个账号，不共用；运营账号强制两步验证（P1，E3 放量前完成）

## 7. 合规要求（实现时必须满足）
- 同意记录可追溯（Consent 表，带版本号）
- 最少收集：**不收集**种族、宗教、身份证号 / 护照号、婚姻状况、照片（头像可选）
- 联系方式加密存储；简历文件私有存储，只通过签名 URL 访问（有效期 ≤ 5 分钟）
- 上传文件按用途白名单校验类型、大小和文件头；不收 SVG、HTML
- 所有解锁、查看、下载、点数变动、后台操作都写审计日志
- 数据访问 / 删除请求在 21 天内完成 ⚠️（以律师意见为准）
- 隐私政策和用户协议提供中英双语，带版本号
- 子处理者和跨境传输：见 `SUBPROCESSORS.md`，隐私政策要如实披露（律师确认）
- 泄露通报：默认向个人资料保护专员 72 小时内、向受影响的人 7 天内通报 ⚠️（时限待律师核实，见 DECISIONS D10）
- 备份里已删除的数据最多再保留 30 天；对象存储里文件的旧版本 30 天后过期

## 8. 非功能需求
- 语言：上线时中文、英文；马来文在 M10
- 移动端优先的响应式网页（学生大多用手机），可安装为 PWA；每个页面在 375px 宽度下不能横向滚动
- 支持的浏览器：iOS Safari、Android Chrome、微信内置浏览器
- 可访问性：WCAG 2.2 AA
- 首屏 LCP < 2.5s（4G 网络）
- 可用性目标 99.5%；数据库每日加密备份，保留 30 天
- 恢复目标：试点期 RPO ≤ 24 小时、RTO ≤ 4 小时；开始收费前 RPO ≤ 1 小时
- 时区 Asia/Kuala_Lumpur；货币 MYR
